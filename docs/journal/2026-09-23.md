# 2026-09-23 업무일지

## 오늘의 목표

- 판매자가 상품과 가상 매장 설정을 로그인 계정에 저장하고 다른 기기에서 이어서 작업할 수 있는 최소 서버 동기화를 구현한다.
- 브라우저 데이터와 서버 데이터가 사용자의 선택 없이 덮어써지지 않도록 저장·불러오기 흐름을 분리한다.

## 수행한 작업

- Sites의 ChatGPT 로그인 사용자 ID를 기준으로 판매자 작업공간을 저장하는 Cloudflare D1 테이블과 마이그레이션을 추가했다.
- 상품 최대 100개와 가상 매장 설정 1개를 하나의 버전이 있는 스냅샷으로 검사하는 데이터 계약을 추가했다.
- 인증된 사용자만 자신의 작업공간을 조회·저장할 수 있는 `/api/seller/workspace` GET·PUT API를 구현했다.
- 요청 크기를 256KB로 제한하고 잘못된 JSON, 규격 오류, 로그인 누락, 데이터베이스 장애를 구분해 안내하도록 했다.
- 모든 판매자 페이지의 상단에 `계정 동기화` 버튼을 추가했다.
- 서버 저장과 이 기기로 불러오기를 각각 명시적인 확인 창으로 분리하고, 서버 저장 건수와 마지막 갱신 시각을 표시했다.
- 상품 사진, 체형 사진, 이용자 보관함이 서버에 포함되지 않는다는 범위를 동기화 창에 표시했다.
- 모바일에서 동기화 버튼을 아이콘으로 줄이고 동기화 창의 좌우 여백을 유지하도록 조정했다.

## 검증 결과

- 전체 자동 검사 64개가 통과했다.
- 변경 파일 TypeScript 검사와 Sites 프로덕션 빌드가 통과했다.
- 로그인하지 않은 동기화 API 요청이 401로 거절되고 화면에 로그인 필요 상태가 표시되는 것을 확인했다.
- 로컬 모의 계정으로 상품 1개를 PUT 저장한 뒤 GET 재조회했을 때 상품 내용과 갱신 시각이 동일하게 반환되는 것을 확인했다.
- 390px 모바일 화면에서 문서 너비 390px, 동기화 창 너비 366px로 가로 넘침이 없음을 확인했다.

## 확인된 한계

- 이용자 보관함과 관심 신호는 현재 기기 안에만 저장된다.
- 판매자 데이터를 서버에서 불러오면 현재 브라우저의 상품·매장 설정을 통째로 교체하며 자동 병합은 지원하지 않는다.
- 상품 사진은 아직 서버에 저장하지 않는다. 파일 저장 기능을 추가하려면 R2와 파일 소유권 검사가 필요하다.
- 교육용 OpenAI 키가 속한 프로젝트가 보관 상태여서 실제 광고 생성 평가는 계속 보류한다.
