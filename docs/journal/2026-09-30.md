# 2026-09-30 개인 업무일지 초안

## 오늘 목표

첫 실제 모델 평가에서 드러난 광고 문구 품질 문제를 고치고 제출물(GitHub 링크, 보고서 PDF)을 마감 전에 마무리한다.

## 완료한 작업 (Claude Code 보조)

- 9월 29일 실제 생성 초안 12개를 다시 읽고 문제를 정리했다. 추가 요청 문장이 본문에 그대로 들어갔고, 신상 홍보에 신상 표현이 없었고, 활기찬 말투가 약했고, 같은 마지막 안내와 문장이 반복됐고, 본문이 항목 나열식이었다.
- 원인은 프롬프트에 있었다. 말투, 광고 목적, 마지막 안내 값이 JSON으로만 전달되고 프롬프트에는 그 값을 쓰는 방법이 없었다. 평가 입력 중 두 건은 추가 요청("짧고 친근하게")이 말투 설정(미니멀, 활기)과 충돌해서 말투에 맞게 바꿨다. 첫 실행 원본 파일은 그대로 두었다.
- 프롬프트를 다섯 번 고쳤다(`2026-09-30.1`~`.5`). 값별 문체·목적 기준, 요청 문장 인용 금지, 판매가는 할인이 반영된 금액, 착용 효과 금지, blader/humanizer(MIT)의 AI 문투 패턴을 옮긴 문체 규칙, 소재를 이유로 한 효과 금지, 비어 있는 항목을 모델 요청에서 빼는 것이다.
- 자동 검사에 요청 문장 인용, 목적 표현 누락, 반복 문장·같은 마지막 안내·같은 시작, 입력 없음 언급, AI 문투 후보, 판매가·착용 효과·소재를 이유로 한 효과를 찾는 검사를 추가했다.
- 첫 재실행에서 첫 호출이 30초 제한에서 시간 초과돼 추론 강도를 `low`로 낮추고 대기 한도를 45초로 늘렸다. 실제 모델 호출 56회 중 2회가 시간 초과됐고 원인은 확인하지 못했다.
- 같은 4개 입력을 판마다 다시 생성해 버전별로 집계했다(`.2`판부터 판마다 3회). AI 문투 후보 단어는 24개에서 6개로 줄었고 "소재 정보는 제공되지 않았습니다"는 0건이 됐다. 정가·착용 효과 의심 표현과 소재를 이유로 한 효과는 2/12건씩 남았고, 평가어가 든 초안은 첫 판(1/12개)보다 많다(14/36개). 판마다 12건이라 작은 차이는 편차와 구분되지 않고, 개선 항목을 같은 입력을 읽고 정했으므로 독립 검증이 아니다.
- 이 평가에는 사용자가 채팅으로 건넨 교육용 API 키를 실행마다 환경변수로만 썼고 파일, Git, 문서에는 남기지 않았다.
- 보고서 PDF·DOCX와 저장소 문서의 문장을 blader/humanizer의 패턴 기준으로 다듬었다. 사실, 수치, AI 도구 사용 표기는 바꾸지 않았다.
- 커밋 기록 전체에서 API 키·토큰 패턴, 개인 이메일, 연락처가 없는 것을 확인하고 사용자의 지시로 GitHub 저장소를 공개로 바꿨다. 작성자 이메일은 GitHub noreply 주소다.
- 자동 검사 112개, 타입 검사, 평가 사전 검사가 통과했다. 결과 원문은 `docs/evaluations/runs/`와 `runs/repeats/`에 있다.
