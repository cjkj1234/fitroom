# 2026-09-30 개인 업무일지 초안

## 오늘 목표

첫 실제 모델 평가에서 드러난 광고 문구 품질 문제를 고치고 제출물(GitHub 링크, 보고서 PDF)을 마감 전에 마무리한다.

## 완료한 작업 (Claude Code 보조)

- 9월 29일 실제 생성 초안 12개를 다시 읽고 문제를 정리했다: 추가 요청 문장이 본문에 그대로 들어감, 신상 홍보에 신상 표현 없음, 활기찬 말투 약함, 같은 마지막 안내와 같은 문장의 반복, 항목 나열식 본문.
- 원인을 프롬프트에서 찾았다. 말투·광고 목적·마지막 안내 값이 JSON으로만 전달되고 프롬프트에는 그 값을 어떻게 쓰라는 설명이 없었다. 평가 입력 중 두 건은 추가 요청("짧고 친근하게")이 말투 설정(미니멀·활기)과 충돌했다.
- 프롬프트를 `2026-09-30.1`로 고쳤다(값별 문체·목적·마지막 안내 기준, 추가 요청 인용 금지, 항목 나열 금지, 초안 간 반복 금지).
- 자동 검사에 요청 문장 인용, 목적 표현 누락, 초안 간 반복 문장, 같은 마지막 안내를 찾는 `styleReview`를 추가했다. 첫 실행 결과에 적용하면 정상 입력 4건 모두에서 후보가 나온다.
- 충돌하던 평가 입력 두 건의 추가 요청을 말투에 맞게 바꿨다. 첫 실행 원본 파일은 그대로 두었다.
- 개정 프롬프트로 실제 모델을 처음 다시 실행하자 첫 호출이 30초 제한에서 시간 초과됐다(이전 실행은 14.8–22.5초). 추론 강도를 `low`로 낮추고 대기 한도를 45초로 늘렸다. 재실행 12회 중 2회가 시간 초과됐고 원인은 확인하지 못했다.
- 2차 생성 결과를 읽어 보니 형식 문제는 없어졌지만 판매가 26,100원을 "정가"로 쓰거나 "하루 종일 편하게"처럼 입력에 없는 착용 효과를 단정하는 문장이 새로 생겼다. 프롬프트를 `2026-09-30.2`로 다시 고쳤다(판매가는 이미 할인 반영 금액, 착용 효과와 "정보가 제공되지 않았다" 문장 금지). 자동 검사에도 이 항목들을 추가했다.
- 3차 결과에서 이런 후보는 4건에서 1건으로 줄었고 응답 시간은 평균 6.7초였다(1차 19.1초, 추론 강도가 다르다). 다만 평가어가 든 초안이 12개 중 1개에서 9개로 늘었다. 개선 항목을 같은 4개 입력을 읽고 정했으므로 독립 검증이 아니다.
- 저장소 공개 전환 전에 커밋 기록 전체에서 API 키·토큰 패턴, 개인 이메일, 연락처가 없는 것을 확인하고 GitHub 저장소를 공개로 바꿨다(작성자 이메일은 GitHub noreply 주소).
- 자동 검사 108개, 타입 검사, 평가 사전 검사가 통과했다. 세 번의 실제 모델 결과는 `docs/evaluations/runs/`에 있다.
