## 후속 작업 — 2단계 입력·출력 설계

- 사용자가 교육 과정 제공 OpenAI API 사용 가능을 확인했다. 제공 범위에서 진행하며 실제 API 키는 요청하거나 읽지 않았다.
- 매장명·상품명·종류·색상·상품 특징을 필수 입력으로, 소재·판매가·할인율을 선택 입력으로 정리했다. 할인 홍보를 선택하면 할인율은 필수다.
- 결과를 상품 특징·코디 제안·일상 장면 관점의 초안 3개로 정했다. 각 초안의 제목·본문·마지막 안내·해시태그를 편집하는 흐름을 설계했다.
- OpenAI 공식 모델 문서와 Structured Outputs 문서를 확인했다. 과제 허용 목록에 있는 `gpt-5-mini`를 시작 모델로 선정하고 서버에서 Responses API를 연결하는 방향을 정했다.
- `docs/AD_CREATION_SPEC.md`, `docs/ads/`의 규격·가상 예시·평가 입력·실행 가능한 검사 코드를 작성했다. 실제 웹사이트에 아직 연결하지 않은 설계용 파일이다.
- 정상 입력 4개와 오류 입력 4개, 예시 결과, 결과 누락·중복·길이 초과, 예상하지 않은 사진 필드, 모델 출력 스키마 구조 검사를 실행해 통과했다.
- 모델 호출은 실행하지 않았다. 생성 품질, 사실 보존, 속도, 교육 계정 권한은 아직 검증하지 않았다.
- 다음 작업은 판매자 입력 화면과 API 연결 구현이다. 이 후속 작업도 Codex의 설계·문서·검사 코드 작성 지원을 받았다.

## 후속 작업 — 3단계 광고 스튜디오 구현

- 기존 사이트 첫 화면을 판매자용 광고 스튜디오로 바꾸고 3D 피팅룸은 ‘3D 코디 열기’로 계속 사용할 수 있게 했다.
- 상품 이미지, 매장·상품 정보, 광고 대상·말투·목적·CTA 입력 화면을 구현했다. 선택한 이미지는 브라우저에서만 미리보기와 PNG 카드 생성에 사용한다.
- 서버에서 `gpt-5-mini` Responses API를 호출하고 Structured Outputs를 요구하는 경로를 구현했다. 입력하지 않은 상품 성능과 사실을 만들지 않도록 프롬프트 정책과 응답 후 검사를 함께 적용했다.
- 초안 3개 선택·편집, 변경된 입력 표시, 복사, TXT 다운로드, PNG 광고 카드 다운로드를 구현했다.
- 광고 계약 검사 4개와 기존 피팅룸 검사 18개, 타입 검사, 배포 빌드가 통과했다. API 비밀값이 없는 로컬 환경에서는 실제 문구 대신 ‘연결 설정 필요’ 오류가 표시되는 것을 확인했다.
- 실제 API 생성 결과의 사실 보존·말투·응답 속도 평가는 아직 수행하지 않았다. 교육용 API 비밀값을 안전하게 연결한 뒤 고정 입력으로 평가해야 한다.
