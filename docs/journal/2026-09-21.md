# 2026-09-21 업무일지

이 문서는 코드·자동 검사·로컬 화면 점검에서 확인한 사실을 바탕으로 작성한 기록 초안이다. 작성자의 개인적인 느낌과 학습 경험은 임의로 채우지 않았다.

## 오늘의 목표

- 외부 계정 로그인이나 API 비밀값 없이 진행할 수 있는 광고 스튜디오 품질 점검을 마친다.
- 입력 오류와 서버 실패가 판매자에게 안전하고 이해하기 쉽게 표시되는지 확인한다.
- 현재 검증 결과를 보고서와 업무일지에 남긴다.

## 수행한 작업

- 판매가·할인율 입력이 숫자, 쉼표, `원`, `%`만 허용하도록 파싱을 강화했다. `가격 29000`처럼 문자와 숫자를 섞은 값은 모델 요청 전에 거부한다.
- 숫자 형식 오류가 Zod 내부 영어 문구로 노출되지 않도록 `판매가는 숫자로 입력해 주세요.` 같은 한국어 안내를 추가했다.
- TXT·PNG 저장 파일명에서 경로 문자와 운영체제 예약 문자를 제거하고, 다운로드 직후 객체 URL이 너무 빨리 해제되지 않도록 정리했다.
- 광고 생성 요청 본문을 32KB로 제한했다.
- 서버 로그에서 상점명·상품명·특징·고객층을 제외하고 요청 ID, 결과, 모델, 프롬프트 버전, 소요 시간, 안전한 오류 코드만 남기도록 변경했다.
- 공급자가 성공 상태로 잘못된 JSON을 반환해도 내부 내용 대신 안전한 응답 형식 오류로 처리하도록 보완했다.
- 판매자와 일반 이용자의 목적이 다르다는 의견을 반영해 첫 화면을 역할 선택 페이지로 바꿨다. 판매자 광고 스튜디오는 `/seller`, 이용자 3D 옷장은 `/wardrobe`로 분리했다.
- 각 기능 페이지의 상단에서 역할 선택 화면이나 다른 역할의 페이지로 이동할 수 있게 했다.

## 검증 결과

- 광고 기능 검사 13개와 기존 3D 피팅룸 검사 18개, 총 31개가 통과했다.
- TypeScript 타입 검사와 배포 빌드가 통과했다.
- 로컬 브라우저에서 광고 스튜디오 초기 화면과 다음 상태를 확인했다.
  - 잘못된 판매가: 한국어 숫자 입력 안내 표시
  - 빈 필수 상품명: 필수 입력 안내 표시
  - API 비밀값 미설정: 교육용 OpenAI API 연결 설정 안내 표시
  - `/` → `/seller` → `/wardrobe` → `/`: 역할별 경로와 상호 이동
- 1240px와 780px 기준 반응형 CSS에서 결과 영역 이동, 한 열 배치, 입력 쌍의 세로 배치 규칙을 확인했다.

## 확인된 한계

- 실제 OpenAI 모델 호출은 하지 않았다. 생성 문구의 사실 보존, 말투, 활용 가능성, 응답 시간은 아직 측정하지 않았다.
- 실제 휴대전화에서의 터치 조작과 화면 캡처 점검은 남아 있다.
- GitHub 제출 저장소 생성, API 비밀값 연결, 새 광고 화면 배포는 외부에서 처리하기 어려운 작업이라 사용자가 돌아온 뒤 진행하기로 했다.
- 판매자 입력 상품을 저장해 이용자 카탈로그에 게시하는 계정·상품 관리 기능은 아직 구현하지 않았다.
