# FITROOM — 의류 소상공인을 위한 코디·광고 문구 제작

작성일: 2026-09-16 · 단계: 광고 스튜디오 구현·로컬 검증 완료, API 비밀값 연결 대기

## 1. 한 문장 소개

작은 의류 매장 운영자가 상품 정보와 코디를 바탕으로 SNS 광고 문구를 만들고, 수정한 결과를 이미지와 함께 저장하는 서비스.

## 2. 사용자와 해결할 문제

- 사용자: 광고 제작에 별도 인력이나 충분한 예산을 쓰기 어려운 의류 소상공인.
- 상황: 새 옷을 판매할 때마다 상품 소개와 SNS 게시물을 직접 작성해야 한다.
- 해결: 판매자가 상품의 사실 정보와 원하는 분위기를 입력하면 생성형 AI가 광고 초안을 제안한다. 판매자는 내용을 확인·수정한 뒤 사용할 수 있다.
- 기존 FITROOM의 역할: 3D 옷장을 코디 구상과 참고 이미지 제작에 활용한다.

## 3. 첫 버전의 핵심 흐름

1. **상품 준비:** 매장명, 상품명, 종류, 색상, 판매자가 확인한 특징을 입력한다. 소재·가격·할인 정보는 선택 사항이다.
2. **이미지와 코디 준비:** 판매자 상품 사진을 선택하거나 기존 3D 옷장에서 참고 코디를 만든다.
3. **광고 조건 선택:** SNS 게시물용으로 시작하며, 고객층과 말투를 선택한다.
4. **AI 문구 생성:** 제목, 짧은 본문, 행동 유도 문구, 해시태그를 포함한 초안 3개를 제안한다.
5. **검토와 수정:** 초안 하나를 고르고 모든 문구를 직접 수정한다.
6. **저장:** 문구 복사·텍스트 다운로드, 선택 이미지와 수정한 문구로 만든 광고 카드 PNG 다운로드를 제공한다.

SNS 계정에 실제 게시하는 기능은 포함하지 않는다. 초안 생성과 파일 저장까지를 첫 버전의 완료 흐름으로 삼는다.

## 4. 첫 버전의 기능 범위

| 기능 | 완료 조건 |
| --- | --- |
| 판매자 상품 정보 입력 | 실제 판매 상품 정보를 입력·수정할 수 있고 필수 항목을 검사한다. |
| 코디 참고 화면 | 기존 아바타 회전, 옷 착용·교체 기능을 활용할 수 있다. |
| 광고 조건 선택 | 고객층과 말투가 생성 요청에 반영된다. |
| 생성형 AI 광고 문구 | 실제 모델 호출로 초안 3개를 생성한다. 고정 예문은 생성 결과로 표시하지 않는다. |
| 편집과 저장 | 사용자가 수정한 최종 내용이 복사·다운로드 결과와 일치한다. |
| 실패 처리 | 입력 누락, 모델 연결 실패, 응답 지연, 결과 형식 오류를 안내하고 재시도할 수 있다. |

### 상품·이미지 사용 원칙

- 기존 무신사 상품 8개는 코디 데모 데이터다. 판매자가 등록한 자기 상품과 구분한다.
- 새로운 상품 사진을 올렸다고 해서 그 옷의 정확한 3D 모델이 자동 생성되지는 않는다.
- 광고 카드에 실제 판매자 사진을 사용하거나, 3D 이미지를 쓰는 경우 참고 코디라는 표시를 유지한다.
- 입력하지 않은 소재, 원산지, 할인율, 재고, 성능, 신체 보정 효과 등을 모델이 임의로 사실처럼 추가하지 않도록 한다.
- 현재 핏 수치를 근거로 ‘완벽한 핏’ 등 검증되지 않은 광고 주장을 생성하지 않는다.

## 5. 이후 확장할 기능

생성형 광고 이미지, 상품 사진에서의 정보 추출, 사진으로 의상 3D 자산 생성, 사진 체형 추정 정확도 개선, 무신사 자동 연동, 여러 광고 매체 규격, SNS 자동 게시는 제출 핵심 기능을 완성한 뒤 검토한다.

기존 체형·사진 추정 기능은 이미 만든 자산으로 보존한다. 이번 제출의 AI 성과는 광고 생성과 그 평가를 중심으로 설명한다.

## 6. 모델과 비용

- 서버의 광고 생성 경로를 `gpt-5-mini` Responses API와 Structured Outputs로 구현했다. 배포 환경의 API 비밀값 연결 전이므로 실제 생성 품질·속도 검증은 아직 수행하지 않았다.
- 사용자는 2026-09-16에 교육 과정 제공 OpenAI API 사용 가능을 확인했다. 해당 제공 범위에서 진행하며 별도의 유료 서비스 구매는 예정하지 않는다.
- 과제 허용 모델인 `gpt-5-mini`와 Responses API를 사용하는 방향으로 정했다. 실제 키 설정·계정 권한·연결 동작은 구현 단계에서 확인한다.
- 사전 학습 모델 활용을 우선 검토한다. 추가 학습은 필수 범위로 잡지 않으며, 보고서에서는 실제로 수행한 모델 선정·프롬프트 실험·평가를 구분해 적는다.
- 모델이 연결되지 않으면 연결 필요 상태를 표시한다. 예시 결과와 실제 생성 결과를 구분한다.
- API를 쓰는 경우 키는 서버 환경변수로 관리하고, 브라우저 코드·GitHub·업무일지에 넣지 않는다.
- 광고 생성에는 상품 텍스트와 광고 조건만 보내는 방식부터 구현한다. 체형 사진과 원본 상품 사진은 이 텍스트 생성 요청에 포함하지 않는다.

## 7. 평가 계획

아래는 앞으로 실행할 평가 계획이며, 아직 측정 결과가 아니다.

| 항목 | 확인 방법 |
| --- | --- |
| 상품 사실 보존 | 생성 문구의 소재·색상·가격·할인 등 주장을 입력과 대조한다. |
| 요청 반영 | 지정한 고객층과 말투를 반영하는지 정해진 기준으로 사람이 평가한다. |
| 안정성 | 같은 정상 입력으로 3회 생성하고 형식·사실 보존을 비교한다. |
| 오류 대응 | 필수 정보 누락, 긴 입력, 모델 연결 실패, 잘못된 응답을 검사한다. |
| 생성 속도 | 모델·실행 환경·입력 조건과 함께 응답 시간을 기록한다. |
| 사용성 | 처음 사용하는 사람이 입력 → 생성 → 수정 → 저장을 끝낼 수 있는지 확인한다. |
| 저장 결과 | 수정된 문구와 이미지가 다운로드 파일에 제대로 반영되는지 확인한다. |

평가용 고정 입력은 정상 상품 4개와 누락·오류 사례 4개로 시작한다. 평가 입력, 모델 설정, 결과, 판단 근거를 함께 남긴다. 현재 광고 계약·요청 검사 6개와 기존 피팅룸 검사 18개가 통과했다. 이 자동 검사는 실제 생성 품질 평가와 별도로 기록한다.
