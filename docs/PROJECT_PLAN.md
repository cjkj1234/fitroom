# FITROOM: 의류 소상공인을 위한 코디·광고 문구 제작

작성일: 2026-09-16 · 갱신일: 2026-09-30 · 단계: 실제 API 평가와 프롬프트 개정 후 재평가 완료(사용자 종합 평가 3.5/5 반영), 클릭 착용·마네킹 핏·사진 색상 추출 추가, GitHub 저장소 게시 완료(9/29 비공개, 9/30 공개 전환)

## 1. 한 문장 소개

작은 의류 매장 운영자가 상품 정보와 코디를 바탕으로 SNS 광고 문구를 만들고, 수정한 결과를 이미지와 함께 저장하는 서비스.

## 2. 사용자와 해결할 문제

- 핵심 사용자: 광고 제작에 별도 인력이나 충분한 예산을 쓰기 어려운 의류 소상공인.
- 보조 사용자: 판매자가 준비한 상품을 자신의 체형에 가깝게 코디해 보려는 일반 이용자.
- 상황: 새 옷을 판매할 때마다 상품 소개와 SNS 게시물을 직접 작성해야 한다.
- 해결: 판매자가 상품의 사실 정보와 원하는 분위기를 입력하면 생성형 AI가 광고 초안을 제안한다. 판매자는 내용을 확인·수정한 뒤 사용할 수 있다.
- 역할 구분: 판매자는 별도 광고 제작 페이지를 사용하고, 일반 이용자는 별도 3D 옷장 페이지를 사용한다. 과제의 생성형 AI 평가 대상은 판매자 흐름이다.

## 3. 첫 버전의 핵심 흐름

첫 화면에서 `판매자`와 `옷을 찾는 이용자` 중 역할을 선택한다.

1. 상품 준비: 매장명, 상품명, 종류, 색상, 판매자가 확인한 특징을 입력한다. 소재·가격·할인 정보는 선택 사항이다.
2. 판매 정보와 실측: 가격·재고와 카테고리에 맞는 사이즈 실측을 입력하고 상품 초안을 브라우저에 저장한다.
3. 상품 게시: 준비가 끝난 상품을 이용자 3D 옷장에 게시하고, 판매자의 스마트스토어·자사몰 링크를 연결한다.
4. 이미지 준비: 판매자 상품 사진을 선택해 브라우저에서 미리 보고 광고 카드에 사용한다.
5. 광고 조건 선택: 등록 상품을 불러온 뒤 SNS 고객층과 말투를 선택한다.
6. AI 문구 생성: 제목, 짧은 본문, 행동 유도 문구, 해시태그를 포함한 초안 3개를 제안한다.
7. 검토와 저장: 초안을 직접 수정한 뒤 문구 복사·텍스트 다운로드와 광고 카드 PNG 다운로드를 제공한다.

SNS 계정에 실제 게시하는 기능은 포함하지 않는다. 초안 생성과 파일 저장까지를 첫 버전의 완료 흐름으로 삼는다.

일반 이용자는 별도 `/wardrobe` 페이지에서 가상 상점 거리를 둘러보고 원하는 소상공인 매장에 입장한다. 매장 옷걸이에서 상품을 골라 내 체형의 아바타에 입히고, 다른 상점으로 이동하면서 코디를 이어가며 판매자 실측을 비교한다. 판매자 상품과 매장 설정은 로그인 계정별 서버 저장·불러오기를 지원한다. 서버에 동기화된 데이터 중 게시 검증을 통과한 매장과 상품은 다른 기기의 이용자 옷장에도 표시하며, 이용자 보관함은 현재 브라우저 안에 저장한다.

## 4. 첫 버전의 기능 범위

| 기능 | 완료 조건 |
| --- | --- |
| 판매자 상품 정보 입력 | 실제 판매 상품 정보를 입력·수정할 수 있고 필수 항목을 검사한다. |
| 판매자 상품 관리 | 가격·재고·사이즈 실측·상점 링크를 브라우저에 저장하고 수정·삭제·게시할 수 있다. |
| 판매자 계정 동기화 | 로그인 계정별로 상품 텍스트와 가상 매장 설정을 서버에 저장하고 다른 기기에서 불러올 수 있다. |
| 공개 입점 카탈로그 | 게시 검증을 통과한 서버 매장·상품만 이용자 상점 거리에 노출하고 계정 ID와 초안을 제외한다. |
| 소상공인 3D 가상 상점 | 상점 거리에 게시 매장이 나타나고, 이용자가 매장별 상품을 아바타에 착용·교체하며 코디를 유지한 채 다른 상점으로 이동할 수 있다. |
| 광고 조건 선택 | 고객층과 말투가 생성 요청에 반영된다. |
| 생성형 AI 광고 문구 | 실제 모델 호출로 초안 3개를 생성한다. 고정 예문은 생성 결과로 표시하지 않는다. |
| 편집과 저장 | 사용자가 수정한 최종 내용이 복사·다운로드 결과와 일치한다. |
| 실패 처리 | 입력 누락, 모델 연결 실패, 응답 지연, 결과 형식 오류를 안내하고 재시도할 수 있다. |

### 상품·이미지 사용 원칙

- 기존 8개 상품은 소상공인 입점 흐름을 보여주는 시연 데이터다. 판매자가 직접 게시한 상품과 화면에서 구분한다.
- 새로운 상품 사진을 올렸다고 해서 그 옷의 정확한 3D 모델이 자동 생성되지는 않는다.
- 광고 카드에 실제 판매자 사진을 사용하거나, 3D 이미지를 쓰는 경우 참고 코디라는 표시를 유지한다.
- 입력하지 않은 소재, 원산지, 할인율, 재고, 성능, 신체 보정 효과 등을 모델이 임의로 사실처럼 추가하지 않도록 한다.
- 현재 핏 수치를 근거로 ‘완벽한 핏’ 등 검증되지 않은 광고 주장을 생성하지 않는다.
- 판매자 서버 동기화에는 상품 텍스트와 매장 설정만 포함하며 상품 사진·체형 사진·이용자 보관함은 포함하지 않는다.

## 5. 이후 확장할 기능

자유 보행형 3D 거리와 다른 이용자 아바타가 보이는 실시간 멀티플레이, 생성형 광고 이미지, 상품 사진에서의 정보 추출, 사진으로 의상 3D 자산 생성, 사진 체형 추정 정확도 개선, 이용자 보관함·관심 신호의 계정 동기화, 여러 광고 매체 규격, SNS 자동 게시는 제출 핵심 기능을 완성한 뒤 검토한다.

기존 체형·사진 추정 기능은 이미 만든 자산으로 보존한다. 이번 제출의 AI 성과는 광고 생성과 그 평가를 중심으로 설명한다.

### 5.1 2026-09-29 추가한 것과 한계

- 검사 중 찾아 고친 결함: 광고 스튜디오에서 하의·모자 상품을 불러오면 카테고리가 비던 문제, 상품 등록에서 카테고리를 바꾸면 숨은 실측값이 저장을 막던 문제, 기본 상점명이 시연 상점과 같아 시연 상품이 섞이던 문제.
- 광고 스튜디오: 등록 상품 선택기, 사진을 고르기 전에는 "참고 이미지" 표시(PNG 카드 포함).
- 피팅룸 조작: 클릭으로 입기·벗기기(카드·아바타의 옷·"지금 입은 옷"·모두 벗기).
- 3D 의상: 마네킹을 높이별로 실측한 몸 중심선에 옷을 맞추고, 마네킹 정점이 옷 밖으로 나오는 비율을 자동 검사한다(`lib/wardrobe/mannequin-fit.test.ts`).
- 상품 사진: 사진에서 대표색 후보를 찾아 3D 표시 색상으로 제안한다. 사진 자체는 저장하지 않는다. 이름·특징에 "셔츠", "카펜터/카고"가 적힌 경우 오픈카라 셔츠·카펜터 바지 세부를 그린다.
- 사진 앞면 텍스처(최소 버전): 평면 촬영한 상의 사진에서 윤곽을 따 몸통 앞면을 3D 상의에 입힌다. 판매자가 체크했을 때만, 이 브라우저 탭의 sessionStorage에서만 유지한다(서버·계정·localStorage 미저장). 상의 앞면만 지원한다.
- 한계: 사진에서 3D 형태를 자동 생성하지는 않는다. 3D는 실측·색상·문구를 기본 의상 형태에 적용한 참고 표현이며, 실제 원단·세부 디자인·착용 결과와 같다고 검증하지 않았다.

## 6. 모델과 비용

- 서버의 광고 생성 경로를 `gpt-5-mini` Responses API와 Structured Outputs로 구현했다. 2026-09-29에 로컬에서 교육용 키로 정상 입력 4건을 실제 생성했다(아래 7장). 배포 사이트에는 서버 비밀값(`OPENAI_API_KEY`)이 아직 연결되지 않아 배포 환경에서의 생성은 확인하지 않았다.
- 2026-09-30 재평가에서는 사용자가 채팅으로 건넨 교육용 키를 실행마다 환경변수로만 썼고 파일, Git, 문서에는 남기지 않았다.
- 사용자는 2026-09-16에 교육 과정 제공 OpenAI API 사용 가능을 확인했다. 해당 제공 범위에서 진행하며 별도의 유료 서비스 구매는 예정하지 않는다.
- 과제 허용 모델인 `gpt-5-mini`와 Responses API를 사용하는 방향으로 정했다. 키 권한과 연결 동작은 처음에 보관(archived)된 프로젝트의 키가 401(`not_authorized_invalid_project`)로 거절되는 것을 확인했고, 9/29에 활성 프로젝트의 키로 정상 동작을 확인했다.
- 사전 학습 모델 활용을 우선 검토한다. 추가 학습은 필수 범위로 잡지 않으며, 보고서에서는 실제로 수행한 모델 선정·프롬프트 실험·평가를 구분해 적는다.
- 모델이 연결되지 않으면 연결 필요 상태를 표시한다. 예시 결과와 실제 생성 결과를 구분한다.
- API를 쓰는 경우 키는 서버 환경변수로 관리하고, 브라우저 코드·GitHub·업무일지에 넣지 않는다.
- 광고 생성에는 상품 텍스트와 광고 조건만 보내는 방식부터 구현한다. 체형 사진과 원본 상품 사진은 이 텍스트 생성 요청에 포함하지 않는다.

## 7. 평가 계획

아래 표는 평가 계획이다. 2026-09-29에는 오류 대응(오류 입력 4/4건 모델 호출 전 거부), 생성 속도(정상 입력 4건 평균 19.1초, 14.8–22.5초), 사실 보존·톤·활용 가능성의 Codex 보조 검토(사람 평가 아님)를 측정했고 결과는 [docs/evaluations/runs](evaluations/runs/2026-09-29T00-23-32-748Z.md)에 있다. 이 결과를 읽고 프롬프트를 다섯 번 고쳐(2026-09-30) 같은 입력을 판마다 3회씩 다시 생성했으며, 버전별 비교와 한계는 [평가 안내](evaluations/README.md)에 있다. 사용자는 최종 프롬프트의 초안 12개를 읽고 종합 3.5/5로 평가했다(항목별 점수 없음, 평가자 1명). 처음 쓰는 사람의 사용성 확인은 아직 하지 않았다.

| 항목 | 확인 방법 |
| --- | --- |
| 상품 사실 보존 | 생성 문구의 소재·색상·가격·할인 등 주장을 입력과 대조한다. |
| 요청 반영 | 지정한 고객층과 말투를 반영하는지 정해진 기준으로 사람이 평가한다. |
| 안정성 | 같은 정상 입력으로 3회 생성하고 형식·사실 보존을 비교한다. |
| 오류 대응 | 필수 정보 누락, 긴 입력, 모델 연결 실패, 잘못된 응답을 검사한다. |
| 생성 속도 | 모델·실행 환경·입력 조건과 함께 응답 시간을 기록한다. |
| 사용성 | 처음 사용하는 사람이 입력, 생성, 수정, 저장을 끝낼 수 있는지 확인한다. |
| 저장 결과 | 수정된 문구와 이미지가 다운로드 파일에 제대로 반영되는지 확인한다. |

평가용 고정 입력은 정상 상품 4개와 누락·오류 사례 4개로 시작한다. 평가 입력, 모델 설정, 결과, 판단 근거를 함께 남긴다. 판매자 상품·게시·계정 동기화·공개 카탈로그 계약, 광고 기능, 피팅룸, 마네킹 핏, 사진 색상 추출을 포함한 자동 검사 112개가 2026-09-30 기준 통과했다. 이 자동 검사는 실제 생성 품질 평가와 별도로 기록한다.
