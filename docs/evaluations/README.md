# 광고 문구 평가 실행 방법

## 광고 스튜디오에서 한 건씩 평가

`/seller/ads`에서 광고 문구 생성에 성공하면 화면 아래의 `AI 생성 품질 평가`가 활성화된다.

1. 생성 직후 원본과 입력 상품 정보를 비교한다.
2. 사실 보존, 톤·목적 반영, 활용 가능성을 각각 1–5점으로 선택한다.
3. 과장 표현이나 수정이 필요한 문장을 평가 메모에 적는다.
4. `평가 저장`을 누른다.
5. `전체 평가 JSON`을 눌러 보고서 근거 파일을 저장한다.

평가 기록에는 모델명, 프롬프트 버전, 응답 시간, 생성 당시 입력과 수정 전 원본 초안이 함께 들어간다. 최대 50건을 `fitroom.ads.evaluations.v1` 키로 현재 브라우저에 저장한다. JSON에는 상품 입력과 생성 문구가 포함되므로 공개 저장소에 그대로 올리기 전에 내용을 확인한다.

## 고정 입력을 이용한 일괄 평가

평가 입력의 형식만 확인할 때는 API 키가 필요하지 않다.

```sh
npm run evaluate:ads -- --dry-run
```

실제 모델 평가는 `OPENAI_API_KEY`가 서버 실행 환경에 안전하게 설정된 상태에서 아래 명령으로 실행한다. 키를 저장소, 결과 파일, 터미널 명령 인자에 기록하지 않는다.

```sh
npm run evaluate:ads
```

정상 입력 4건을 순서대로 생성해 `docs/evaluations/runs/`에 원본 입력·출력·응답 시간·자동 의심 표현 검사·사람 평가란을 JSON과 Markdown으로 남긴다. 정상적인 광고 표현도 자동 검사에 걸릴 수 있으므로 사람이 입력과 대조해 사실 보존, 말투 반영, 활용 가능성을 최종 판단한다.

- 추가 요청 문장이 본문에 그대로 들어갔다.
- 신상 홍보에 신상 표현이 없었다.
- 활기찬 말투가 약했다. 해당 입력의 추가 요청이 말투와 충돌하고 있었다.
- 같은 마지막 안내와 같은 문장이 반복됐다.

읽는 방법과 한계는 다음과 같다.

- 2차(`.1`)는 형식 문제를 없앴지만 판매가를 "정가"로 쓰고 입력에 없는 착용 효과를 단정하는 문장이 새로 나왔다.
- 문체 규칙을 넣은 뒤(`.3` 이후) AI 문투 후보 단어는 24개(`.2`)에서 6개(`.5`)로 줄었다. 평가어가 든 초안은 21/36개에서 14/36개로 줄었지만 첫 판(1/12개)보다는 많다.
- "제공되지 않았습니다"는 프롬프트로 금지해도 줄지 않다가 `null` 항목을 요청에서 빼자 0/12건이 됐다.
- 소재를 이유로 한 효과와 착용 효과 의심 표현은 최종 판에도 각각 2/12건 남았다.
- 판마다 12건이라 `.4`와 `.5`의 차이 같은 작은 변화는 실행마다 달라지는 편차와 구분되지 않는다.
- 응답 시간은 추론 강도를 낮춘 효과가 섞여 있어 프롬프트만의 효과가 아니다. 실제 모델 호출 56회 중 2회가 시간 초과(30초·45초 제한)됐고 원인은 확인하지 못했다.
- 개선 항목을 같은 4개 입력을 읽고 정했으므로 독립된 검증이 아니다.
- 자동 검사, 키워드 집계, Claude Code의 읽기 검토는 사람 평가가 아니며 사람 평가는 아직 없다.
- 재평가에는 사용자가 채팅으로 건넨 교육용 API 키를 실행마다 환경변수로만 썼고 파일이나 Git에는 남기지 않았다.

`automaticReview`에는 `styleReview`(요청 문장 인용, 목적 표현 누락 초안, 반복 문장, 같은 마지막 안내, 같은 시작, 입력 없음 언급, AI 문투 후보)와 판매가·착용 효과·소재를 이유로 한 효과 의심 표현이 들어 있다. 평가 스크립트는 한 건이 실패해도 나머지를 실행하고 실패를 결과 파일의 `generationFailures`에 남긴다.
