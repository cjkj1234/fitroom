# FITROOM 개발 도구·AI 모델·Codex 스킬 정리

FITROOM에 쓴 프로그램, 기술, AI 모델과 각각의 역할을 정리한다.

## 1. 두 종류의 AI

| 구분 | 사용 모델 | 사용 목적 |
| --- | --- | --- |
| 서비스 기능의 AI | OpenAI `gpt-5-mini` | 판매자가 입력한 상품 정보로 SNS 광고 문구 초안 3개 생성 |
| 개발 보조 AI | Codex의 GPT-6 기반 코딩 에이전트 | 요구사항 정리, 화면·서버 코드 작성, 테스트, 브라우저 점검, 문서 초안 지원(2026-09-15~09-29 오전) |
| 개발 보조 AI (추가) | Claude Code(Anthropic Claude Sonnet 5.5) | 2026-09-29 오후~09-30: 화면 점검으로 찾은 결함 수정, 클릭 착용·탈착, 마네킹 실측 기반 의상 형태·핏 검사, 사진 대표색 추출, 광고 프롬프트 개정과 재평가, 문서·보고서 정리, GitHub 게시 지원. 해당 커밋에는 `Co-Authored-By: Claude Sonnet 5.5`가 남아 있음 |

Codex와 Claude Code는 프로젝트를 만드는 데 쓴 개발 도구이고(시기와 범위는 위 표와 7장에 구분해 적었다), 서비스 이용자가 광고 문구를 만들 때 호출하는 모델은 `gpt-5-mini`다. 보고서에서도 이 둘을 같은 용도로 쓰지 않는다.

## 4. AI·머신러닝 모델

### 4.1 `gpt-5-mini`: 광고 문구 생성

- 입력: 상점명, 상품명, 종류, 색상, 특징, 소재, 가격, 고객층, 말투, 홍보 목적, CTA, 추가 요청. 판매자가 비워 둔 항목은 요청에서 뺀다.
- 출력: 상품 특징·스타일링·일상 장면이라는 서로 다른 관점의 광고 초안 3개
- 호출 방식: OpenAI Responses API. 추론 강도는 `low`
- 출력 통제: Structured Outputs로 제목, 본문, CTA, 해시태그가 포함된 JSON 형식을 요구한다.
- 검증: Zod로 길이, 필수 항목, 세 관점, 제목 중복, 해시태그 개수를 다시 검사한다.
- 선정 이유: 교육 과정에서 허용한 모델이며, 광고 초안 생성에 필요한 품질과 비용·응답 시간을 함께 고려했다.
- 보안: API 키는 브라우저 코드나 Git에 넣지 않고 서버 환경변수 `OPENAI_API_KEY`에서만 읽는다.

실제 API 키가 연결되지 않은 상태에서는 예시 문구를 AI 결과처럼 보여주지 않고 연결 필요 오류를 표시한다. 실제 모델 평가(2026-09-29, 09-30)의 응답 시간과 프롬프트 버전별 비교는 [평가 안내](evaluations/README.md)와 보고서 8.2절에 있다. 버전별 비교는 자동 검사와 Claude Code의 읽기 검토이고, 사용자는 최종 프롬프트의 초안 12개를 읽고 종합 3.5/5로 평가했다(항목별 점수 없음).

### 4.2 MediaPipe Pose Landmarker Lite: 사진의 포즈 지점 탐지

- 모델: Google MediaPipe `pose_landmarker_lite` float16 사전 학습 모델
- 입력: 사용자가 선택한 정면·측면 전신사진
- 출력: 어깨·엉덩이·무릎 등 신체 주요 지점과 인식 신뢰도
- 실행 위치: 브라우저 내부 Worker
- 후처리: 사용자가 입력한 키와 정면 너비·측면 깊이를 이용해 프로젝트에서 작성한 기하학 계산으로 초기 둘레를 추정한다.

MediaPipe는 실제 신체 치수를 직접 측정하지 않는다. 원본 사진은 서버나 OpenAI API로 보내지 않고 메모리에서만 사용한다.

### 4.3 직접 학습하거나 파인튜닝한 모델은 없음

이번 버전은 Hugging Face 모델 학습, LoRA, DreamBooth, 파인튜닝을 사용하지 않았다. 사전 학습된 OpenAI 모델과 MediaPipe 모델을 서비스 흐름에 연결했다.

## 5. AI가 아닌 계산 기능

다음 기능은 AI 모델처럼 보일 수 있지만 규칙과 수식으로 작동한다.

- 예상 핏: 의류 단면을 둘레로 변환한 값과 신체 둘레의 차이를 계산한다.
- 개인화 추천: 찜과 저장 코디에서 같은 상점·종류·색상·실루엣을 찾아 가중치로 점수화한다.
- 판매자 관심도: 현재 찜 4점, 저장 코디 3점, 추천 클릭 2점, 입어보기 1점으로 합산한다.
- 3D 의상: 상품 실측과 분류에 따라 Three.js geometry를 변형한 참고 표현이다. 상품 사진을 AI로 3D 변환한 결과가 아니다.

- 판매자 흐름을 샘플 상품으로 끝까지 눌러 보며 결함을 찾아 고침: 광고 스튜디오 카테고리 빈 값, 카테고리 변경 시 숨은 실측값, 시연 상점명 충돌
- 광고 스튜디오 등록 상품 선택기와 "참고 이미지" 표시
- 카드·아바타 클릭으로 입기·벗기기
- 마네킹 GLB를 높이별로 실측해 의상 형태를 맞추고, 마네킹 정점이 옷 밖으로 나오는 비율을 자동 검사하는 테스트 추가
- 상품 사진에서 대표색을 찾는 기능, 오픈카라 셔츠·카펜터 바지 세부 표현, 평면 촬영 상의 사진의 앞면 텍스처(브라우저 안 윤곽 추출·세션 보관)
- 광고 문구 12개 초안을 읽고 문제를 정리, 프롬프트를 다섯 번 개정(2026-09-30.1~.5), 문체·판매가·착용 효과·입력 없음 언급·반복을 찾는 자동 검사 추가, 실제 모델 재평가 실행과 버전별 집계
- 문서 수치 정리, 새 환경(설치·테스트·타입 검사·빌드) 재현 검사, 보고서 PDF·DOCX 재생성
- 저장소를 iCloud 밖으로 옮겨 GitHub에 게시하고 공개로 전환, 커밋 이메일 수정

이 작업에서도 무엇을 만들지, 어떤 상품 사진으로 확인할지, 실제 화면에서 받아들일지는 사용자가 정했다. 사진을 넣은 실제 상품의 실측값은 사진 비율로 추정한 시험용 값이다.

사용자는 최종 제출 전에 광고 결과를 직접 평가하고, 업무일지의 배운 점·실수·소감과 의사결정 이유를 자신의 경험으로 작성해야 한다.

## 8. 보고서에 사용할 수 있는 짧은 설명

> FITROOM은 React와 TypeScript로 구현한 의류 소상공인용 광고 제작 및 가상 매장 서비스다. 광고 문구 생성에는 OpenAI Responses API의 `gpt-5-mini`와 Structured Outputs를 사용했고, Zod로 입력과 출력 형식을 검증했다. 체형 사진의 포즈 지점 탐지에는 브라우저에서 실행되는 MediaPipe Pose Landmarker Lite를 사용했으며 원본 사진은 서버로 전송하지 않았다. 3D 화면은 Three.js와 MakeHuman 기반 아바타로 구성했다. 개인화 추천과 예상 핏은 별도의 AI 모델이 아니라 설명 가능한 규칙과 치수 계산으로 구현했다. 개발 과정에서는 GPT-6 기반 Codex를 요구사항 정리, 코드 작성, 테스트, 브라우저 검증과 문서 작성 보조 도구로 사용했고, 마지막 결함 수정, 3D 의상 정밀화, 광고 프롬프트 개정과 문서 정리에는 Claude Code(Claude Sonnet 5.5)도 보조 도구로 사용했다.

## 9. 발표나 질의응답에서 정확하게 말할 부분

- `gpt-5-mini`는 직접 학습하지 않고 API로 연결했다.
- MediaPipe의 포즈 지점을 이용해 프로젝트의 계산식으로 초기 체형을 제안한다.
- 추천은 협업 필터링이나 딥러닝 추천 모델이 아니라 설명 가능한 속성 점수 방식이다.
- 판매자 상품 텍스트와 매장 설정은 계정별 서버 동기화를 지원하고 게시한 매장은 다른 기기의 이용자 가상거리에도 표시된다. 이용자 보관함과 관심 신호는 현재 브라우저에만 저장된다.
- 광고 문구는 실제 API로 평가했고 프롬프트 개정 전후를 비교했다. 자동 검사와 키워드 집계는 사람 평가가 아니며 광고의 창의성이나 사실성을 완전히 증명하지 못한다. 사용자의 종합 평가는 3.5/5이고 항목별 점수는 없다.
- Codex와 Claude Code가 개발을 보조했고, 서비스의 생성 기능에 쓰는 모델은 `gpt-5-mini`다.
