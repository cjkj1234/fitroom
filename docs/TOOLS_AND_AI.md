# FITROOM 개발 도구·AI 모델·Codex 스킬 정리

이 문서는 FITROOM을 어떤 프로그램과 기술로 만들었는지, 서비스 안에서 사용하는 AI와 개발을 도운 AI가 무엇인지 구분해 설명한다.

## 1. 가장 먼저 구분할 두 가지 AI

| 구분 | 사용 모델 | 사용 목적 |
| --- | --- | --- |
| 서비스 기능의 AI | OpenAI `gpt-5-mini` | 판매자가 입력한 상품 정보로 SNS 광고 문구 초안 3개 생성 |
| 개발 보조 AI | Codex의 GPT-6 기반 코딩 에이전트 | 요구사항 정리, 화면·서버 코드 작성, 테스트, 브라우저 점검, 문서 초안 지원 |

Codex는 프로젝트를 만드는 과정에서 사용한 개발 도구다. 최종 서비스 이용자가 광고 문구를 만들 때 호출하는 모델은 `gpt-5-mini`다. 보고서에서는 두 모델을 같은 용도로 표현하지 않는다.

## 2. 사용한 프로그램

| 프로그램 | 프로젝트에서 한 일 |
| --- | --- |
| Codex 데스크톱 앱 | 대화로 요구사항을 정리하고 코드 수정, 명령 실행, 브라우저 검증, Git 커밋 수행 |
| 로컬 터미널 | 개발 서버 실행, 자동 검사, 타입 검사, 빌드 명령 실행 |
| 인앱 브라우저 | 판매자·이용자 화면의 버튼 동작, 저장·복원, 데스크톱·모바일 반응형 화면 확인 |
| Git | 기능 단위 변경 이력과 커밋 관리 |
| Node.js | 웹 애플리케이션 실행과 TypeScript 테스트 수행 |
| Python | Three.js 의상 geometry를 이용한 카탈로그 참고 이미지 렌더링 |

현재 Git은 로컬 저장소에서 관리하고 있다. 제출용 GitHub 저장소 연결과 푸시는 별도 단계다.

## 4. AI·머신러닝 모델

### 4.1 `gpt-5-mini` — 광고 문구 생성

- **입력:** 상점명, 상품명, 종류, 색상, 특징, 소재, 가격, 고객층, 말투, 홍보 목적, CTA, 추가 요청
- **출력:** 상품 특징·스타일링·일상 장면이라는 서로 다른 관점의 광고 초안 3개
- **호출 방식:** OpenAI Responses API
- **출력 통제:** Structured Outputs로 제목, 본문, CTA, 해시태그가 포함된 JSON 형식을 요구한다.
- **검증:** Zod로 길이, 필수 항목, 세 관점, 제목 중복, 해시태그 개수를 다시 검사한다.
- **선정 이유:** 교육 과정에서 허용한 모델이며, 광고 초안 생성에 필요한 품질과 비용·응답 시간을 함께 고려했다.
- **보안:** API 키는 브라우저 코드나 Git에 넣지 않고 서버 환경변수 `OPENAI_API_KEY`에서만 읽는다.

실제 API 키가 연결되지 않은 상태에서는 예시 문구를 AI 결과처럼 보여주지 않고 연결 필요 오류를 표시한다. 최종 보고서에는 실제 API 평가 후 응답 시간과 품질 점수를 추가해야 한다.

### 4.2 MediaPipe Pose Landmarker Lite — 사진의 포즈 지점 탐지

- **모델:** Google MediaPipe `pose_landmarker_lite` float16 사전 학습 모델
- **입력:** 사용자가 선택한 정면·측면 전신사진
- **출력:** 어깨·엉덩이·무릎 등 신체 주요 지점과 인식 신뢰도
- **실행 위치:** 브라우저 내부 Worker
- **후처리:** 사용자가 입력한 키와 정면 너비·측면 깊이를 이용해 프로젝트에서 작성한 기하학 계산으로 초기 둘레를 추정한다.

MediaPipe가 실제 신체 치수를 직접 측정하는 것은 아니다. 원본 사진은 서버나 OpenAI API로 보내지 않고 메모리에서만 사용한다.

### 4.3 직접 학습하거나 파인튜닝한 모델은 없음

이번 버전은 Hugging Face 모델 학습, LoRA, DreamBooth, 파인튜닝을 사용하지 않았다. 사전 학습된 OpenAI 모델과 MediaPipe 모델을 서비스 흐름에 연결하는 방식으로 구현했다.

## 5. AI가 아닌 계산 기능

다음 기능은 AI 모델처럼 보일 수 있지만 규칙과 수식으로 작동한다.

- **예상 핏:** 의류 단면을 둘레로 변환한 값과 신체 둘레의 차이를 계산한다.
- **개인화 추천:** 찜과 저장 코디에서 같은 상점·종류·색상·실루엣을 찾아 가중치로 점수화한다.
- **판매자 관심도:** 현재 찜 4점, 저장 코디 3점, 추천 클릭 2점, 입어보기 1점으로 합산한다.
- **3D 의상:** 상품 실측과 분류에 따라 Three.js geometry를 변형한 참고 표현이다. 상품 사진을 AI로 3D 변환한 결과가 아니다.

이 구분은 보고서에서 모델 성능과 일반 기능 검증을 혼동하지 않기 위해 중요하다.

## 6. 사용한 Codex 스킬

Codex의 스킬은 새로운 AI 모델이 아니라, 특정 작업을 수행할 때 따르는 전문 작업 지침이다.

| Codex 스킬 | 사용 내용 |
| --- | --- |
| `sites:sites-building` | React·TypeScript 사이트 구조, 페이지, 컴포넌트, 반응형 UI 구현 |
| `browser:control-in-app-browser` | 로컬 사이트를 직접 열어 클릭 흐름, 저장·복원, 화면 문구, 모바일 가로 넘침 검증 |

이번 구현에서는 생성형 이미지 제작용 `imagegen` 스킬을 사용하지 않았다. 의상 썸네일은 프로젝트의 Three.js geometry를 Python으로 렌더링한 참고 이미지다.

## 7. Codex가 지원한 작업과 사용자가 결정한 작업

### 사용자가 결정한 내용

- 소상공인 의류 판매자를 주요 대상으로 선정
- 판매자와 일반 이용자 페이지 분리
- 메타버스 느낌의 가상 옷가게와 3D 웹 옷장 방향 선택
- 프로젝트 종료일과 교육 과정 제공 OpenAI API 사용 여부 결정
- 단계별 기능 진행 방향 승인

### Codex가 지원한 내용

- 아이디어를 기능 목록과 데이터 구조로 정리
- React·TypeScript 화면과 서버 API 코드 작성
- OpenAI 요청·응답 검사와 안전한 오류 처리 구현
- 3D 옷장, 가상 매장, 보관함, 추천, 관심 대시보드 연결
- 판매자 계정 인증과 D1 서버 동기화 구현
- 자동 검사 작성과 로컬 브라우저 동작 점검
- README, 업무일지, 보고서 초안 작성

사용자는 최종 제출 전에 실제 API 결과를 직접 확인하고, 업무일지의 배운 점·실수·소감과 프로젝트 의사결정 이유를 자신의 경험으로 작성해야 한다.

## 8. 보고서에 사용할 수 있는 짧은 설명

> FITROOM은 React와 TypeScript로 구현한 의류 소상공인용 광고 제작 및 가상 매장 서비스다. 광고 문구 생성에는 OpenAI Responses API의 `gpt-5-mini`와 Structured Outputs를 사용했고, Zod로 입력과 출력 형식을 검증했다. 체형 사진의 포즈 지점 탐지에는 브라우저에서 실행되는 MediaPipe Pose Landmarker Lite를 사용했으며 원본 사진은 서버로 전송하지 않았다. 3D 화면은 Three.js와 MakeHuman 기반 아바타로 구성했다. 개인화 추천과 예상 핏은 별도의 AI 모델이 아니라 설명 가능한 규칙과 치수 계산으로 구현했다. 개발 과정에서는 GPT-6 기반 Codex를 요구사항 정리, 코드 작성, 테스트, 브라우저 검증과 문서 작성 보조 도구로 사용했다.

## 9. 발표나 질의응답에서 정확하게 말할 부분

- `gpt-5-mini`를 직접 학습한 것이 아니라 API로 연결했다.
- MediaPipe의 포즈 지점을 이용해 프로젝트의 계산식으로 초기 체형을 제안한다.
- 추천은 협업 필터링이나 딥러닝 추천 모델이 아니라 설명 가능한 속성 점수 방식이다.
- 판매자 상품 텍스트와 매장 설정은 계정별 서버 동기화를 지원하고, 이용자 보관함과 관심 신호는 현재 브라우저에만 저장된다.
- 광고 품질은 실제 API 평가 전이며, 자동 검사가 광고의 창의성이나 사실성을 완전히 증명하지는 않는다.
- Codex가 개발을 보조했으며 서비스의 생성 기능에 사용하는 모델은 `gpt-5-mini`다.
